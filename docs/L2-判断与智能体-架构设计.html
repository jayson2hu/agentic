L2 判断与智能体 — 架构设计

用 LangGraph 实现一组按职责拆分的智能体（评分/翻译/推荐/伴读），统一在垂直 lens 抽象下运行。核心是让"判断引擎通用、判断标准按垂直配置"，从而既能复用又能差异化。

1设计目标

🧩

引擎通用

评分/翻译/推荐引擎一套，多垂直复用。

⚙️

标准可配

rubric/标签/源过滤按 lens 配置，不改代码。

👤

人在环

精审闭环校准判断，可回溯可调。

🔁

可重放

rubric 升级可对历史重评。

💵

低成本

只吃 L1 产物，不重读全文。

🚪

质量门

未精审不 COMPLETED、不外露。

2组件

content.analyzed ─▶ scoring-worker ─▶ ┌ 评分图(注入 lens.rubric)
                                       ├ 翻译图(中英)
                                       └ → review_queue → COMPLETED
请求时(L3 调用):  recommend 引擎 / companion 引擎(SSE)
配置来源:  verticals 表(lens) — 评分引擎按 vertical_code 取 rubric/标签/源过滤

3垂直 lens 抽象（跨站核心）

verticals(
  code PK,                    # ai-coding / (future) data-eng ...
  name, enabled,
  source_filter jsonb,          # 哪些源/标签属于本垂直
  rubric_prompt,                # 六维评分标准(护城河)
  tag_taxonomy jsonb,           # 垂直标签体系
  brief_template,               # 早报模板(供 L3)
  model_profile jsonb )         # 该 lens 用哪档模型
一个 lens = 一份配置。评分引擎读 vertical_code 加载对应 lens，跑同一套图但注入不同 rubric/标签。加垂直只新增一行 + 一套 prompt，引擎与下层零改动——这就是"跨站"的工程实现。

4Agent 图设计（LangGraph）

① 评分图 scoring_graph(vertical)

relevance_gate(属于该垂直? 否→跳过该 lens)
   └▶ score_6dim(注入 lens.rubric_prompt: 选题/内容/深度/实用/创新/表达)
        └▶ vertical_tag(lens.tag_taxonomy)
             └▶ reflect_check(扮演领域评审专家: 全面/准确/一致)
                  └▶ refine ▶ persist(content_vertical_scores) ▶ review_queue?

② 翻译图 translate_graph(target_lang)

identify_terms ▶ translate ▶ check ▶ refine(意译) ▶ persist(content_translations)

③ 推荐图 / ④ 伴读图（请求时）

recommend: 召回(标签+向量) ▶ 合并去重 ▶ rerank ▶ topN
companion: load(base_analysis+text) ▶ retrieve(相关段) ▶ answer(SSE) ▶ log(quota)
评分图复用 BestBlogs 验证过的"分析→反思→优化"模式：先评分，再让模型扮演评审专家自查全面性/准确性/一致性，最后据反思优化。这比一次性打分稳定得多。

5数据模型

content_vertical_scores(           # content × vertical，每垂直一份
  content_id, vertical_code, relevance,
  dim_scores jsonb {topic,content,depth,practical,novelty,expression},
  vertical_tags jsonb, quality_score,
  reviewed bool, review_note, rubric_version, model,
  PK(content_id, vertical_code) )

content_translations(content_id, lang, fields jsonb, model)
user_interest_vectors(user_id, vector, updated_at)   # 推荐用(L2 计算, L3 触发)
review_queue(content_id, vertical_code, reason, status, reviewer, decided_at)

6召回与重排（推荐）

  • 标签通道：按用户 top 标签精确匹配，按 quality_score × 标签权重 排序。
  • 向量通道：用户兴趣向量 kNN（pgvector），补标签未覆盖的语义相关。
  • 重排：两路合并去重 → quality_score + 标签相关性 + 新鲜度 − 多样性惩罚。
  • Feature Flag 控制是否启用向量通道，关闭则退回纯标签。

7精审闭环（人在环）

低置信（评分边界）或高曝光内容进 review_queue；人工裁决后：① 推进 COMPLETED 或 CANCELLED；② 反馈用于校准 rubric。MVP 由你本人审，后续半自动（高置信自动通过）→ 社区化。

8接口契约

# 输入  content.analyzed {content_id}
# 产物  content_vertical_scores · content_translations（供 L3 只读）
# 请求时  recommend(user_id, vertical) · companion(content_id, q) [SSE]
# 状态  WAIT_SCORE → WAIT_REVIEW → COMPLETED | CANCELLED

9技术选型

编排LangGraph（多图：评分/翻译/推荐/伴读）
运行Python · scoring-worker（异步评分/翻译）+ reader-api 内请求时 agent
召回PostgreSQL（标签）+ pgvector（向量 kNN）
配置verticals 表（lens）+ ConfigKey（模型档/开关）
可观测LangSmith/自建 trace；rubric_version 灰度

10风险

风险应对
评分漂移/不稳定反思-优化模式 + 精审校准 + rubric 版本化
翻译生硬术语识别 + 意译节点 + 抽检
推荐回声室多样性惩罚 + 新鲜度 + 探索比例
判断成本只吃 L1 产物；评分用中端模型；缓存
