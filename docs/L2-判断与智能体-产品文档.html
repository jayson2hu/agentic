L2 判断与智能体 — Judgment & Agent Service

在 L1 的"内容知识"之上做判断与智能处理：这篇内容对某个垂直值不值得读（六维评分）、翻译成中英、为用户推荐、回答用户提问。这是整个平台差异化与护城河所在——判断标准随时间复利，抄不走。

层级：L2 形态：判断 / Agent 服务 客户：L3 信条：按垂直拆分 · 判断即护城河

1是什么

L2 消费 L1 的 content.analyzed，运行一组智能体产出"带判断的结果"。与 L0/L1 最大的不同：L2 是有立场的——它回答"对 AI Coding 而言这篇好不好、值不值得推给这个用户"。

⚖️

判断

垂直相关性 + 六维评分 + 垂直标签 + 精审。

🌐

转化

中英翻译，让分析结果双语可读。

🤖

智能体

推荐/重排、AI 伴读问答、研究/监控（后期）。

2为何是护城河

判断标准是平台唯一抄不走的资产。L0 的数据、L1 的通用分析，竞品理论上都能复制；但"什么是 AI Coding 领域的好内容"这套判断——沉淀在评分 rubric、垂直标签体系、精审规则里——是你领域信誉与持续投入的产物，随时间复利。L2 守住了，整个产品才有不可替代性。

4智能体清单

Agent职责阶段
评分 Agent垂直相关性 + 六维分(选题/内容/深度/实用/创新/表达) + 垂直标签 + 检查反思MVP
翻译 Agent分析结果中英互译（术语识别→翻译→检查→意译）MVP
精审（人在环）低置信/高曝光内容复审，校准标准MVP
推荐/重排 Agent多路召回 + 重排（质量×标签权重+新鲜度−多样性）V1
伴读 QA Agent基于内容的总结/提问/章节跳转（SSE）V1
研究/监控 Agent主题追踪、结构化研究包V2

5垂直 lens（跨站关键）

L2 按"垂直 lens"组织。一个 lens = {源过滤 + 评分 rubric + 垂直标签体系 + 早报模板}。评分是 content × vertical 的——同一篇内容在不同 lens 下分数不同。加一个新垂直 = 配一个新 lens，复用同一组 agent 引擎，这是跨站扩展的核心机制。

6产物契约（对 L3）

  • 产物：content_vertical_scores（relevance + 六维分 + 垂直标签 + reviewed）、content_translations（中英）、推荐结果、伴读回答流。
  • 事件：评分+精审通过后推进 status=COMPLETED，L3 方可消费。
  • 不可见性：未达 COMPLETED 的判断不对外、不进任何公共结果。

8边界：L2 不做什么

  • 不抓取、不存原文——L0。
  • 不做通用内容理解（摘要/实体）——L1（L2 复用其产物）。
  • 不渲染界面、不管账户/计费——L3。
  • 不把未精审判断对外——质量边界。
